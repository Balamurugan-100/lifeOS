# LifeOS

A mobile-first personal operating system. LifeOS keeps every domain — tasks,
habits, and (later) finance, nutrition, fitness, journals, notes, time
tracking, calendar, analytics and AI — as an independent module behind typed
contracts, with the home screen as one consumer rather than the hub.

**This repository implements the LifeOS Foundation:** the app shell, the
Tasks and Habits domains, local-first persistence, and portable export
(spec: `specs/001-lifeos-foundation/`).

## Governance

The project is governed by the ratified constitution
(`.specify/memory/constitution.md`, v1.0.0). Key principles:

1. **Modular domain autonomy** — domains are independent packages; home
   depends on modules, never the reverse.
2. **Simplicity (YAGNI)** — v1 ships the smallest thing that works.
3. **Local-first, future-ready** — everything lives on the device; UUID ids
   and UTC audit timestamps keep a future sync door open.
4. **Explicit boundaries, strong typing, automated tests.**
5. **Documented decisions, incremental delivery.**

## Technology

- **Flutter** stable — pinned to: `Flutter 3.47.5` / `Dart 3.13.4`
  (research.md D-1; run `flutter --version` to confirm).
- **drift + SQLite** for persistence (`packages/storage`, research D-2/D-8).
- **flutter_riverpod** (no codegen) for app state (research D-4).

## Monorepo layout

```text
app/                     Flutter application shell (android, ios targets)
packages/
  core/                  pure Dart: module contract, registry, summaries, ids, dates
  storage/               pure Dart: SQLite connection, audit conventions, migration scaffold
  domains/tasks/         Tasks domain: model, drift schema, repository, summary, module
  domains/habits/        Habits domain: model, schedules, repository, streaks, summary, module
  export/                one-tap JSON export envelope + share-sheet delivery
specs/001-lifeos-foundation/   spec, plan, research, data-model, contracts, tasks
```

Dependencies are one-directional: `domains → core, storage`;
`export → core, storage, domains`; `app → everything`. **No package depends
on `app/`.** Screens live in `app/`; domain packages stay pure Dart.

## Setup

```bash
./tool/bootstrap.sh          # flutter pub get + drift codegen everywhere
```

or manually:

```bash
# per package (or use the script)
cd packages/core && flutter pub get && cd ../..
cd packages/storage && flutter pub get && dart run build_runner build --delete-conflicting-outputs && cd ../..
cd packages/domains/tasks && flutter pub get && dart run build_runner build --delete-conflicting-outputs && cd ../../..
cd packages/domains/habits && flutter pub get && dart run build_runner build --delete-conflicting-outputs && cd ../../..
cd packages/export && flutter pub get && cd ../..
cd app && flutter pub get && cd ..
```

> **Important**: do not commit generated files. `.g.dart` drift output is
> git-ignored and regenerated by build_runner.

## Run

```bash
cd app
flutter run                        # on a connected android/ios device or emulator
```

The foundation registers the Tasks and Habits modules; the home overview,
module settings, and one-tap export are reachable from the home app bar.

## Test

```bash
cd app
flutter test                      # unit + widget tests
flutter test integration_test     # end-to-end flows (headless on the tester)

cd ../packages/core && dart test    # pure Dart packages use dart test
cd ../packages/storage && dart test
cd ../packages/domains/tasks && dart test
cd ../packages/domains/habits && dart test
cd ../packages/export && flutter test
```

Every package passes `flutter analyze`/`dart analyze` with zero warnings.
